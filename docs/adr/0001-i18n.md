# ADR 0001 — Internationalisation (i18n), slice 1

- Status: accepted (2026-10-29, cycle v9)
- Builds on: v7 RTL cycle (`App\Support\Direction`, `<html lang dir>` on every layout, logical CSS only).

## Context
The UI is English-only and there is no way to choose a language, so the RTL work from v7 is unreachable.
The first customers are SMB owners in Pakistan and the Gulf (demo "Northwind Dental"), so Urdu and Arabic
come first. Slice 1 must make the language selectable and translate the chrome every user sees
(layouts, navigation, auth, error pages, website widget), without touching every page at once.

## Options considered
| Option | For | Against |
|---|---|---|
| **A. JSON catalogues `lang/{locale}.json`, English source string as key** (`__('Sign in')`) | Laravel-native, keys are readable in Blade, untranslated keys fall back to the English text automatically, one flat file per language is easy to hand to a translator, parity is trivial to test | Long keys; the same English word in two meanings needs a disambiguating key |
| B. PHP arrays `lang/{locale}/*.php` with short keys (`__('auth.sign_in')`) | Grouping, short keys | Blade becomes unreadable, a missing key renders `auth.sign_in` to users, two places to edit for every new string |
| C. gettext / ICU MessageFormat package | Plural/gender rules | New dependency and tooling for a team of one; not needed yet |

**Decision: A.** Framework validation messages keep coming from the framework's own PHP files (slice 2 adds ur/ar
validation files). Plurals, if needed, use Laravel's `trans_choice` pipe syntax inside the JSON value.

## Supported locales
`config('app.supported_locales')`: an allow-list `code => native name` (`en` English, `ur` اردو, `ar` العربية).
Nothing outside this list is ever passed to `App::setLocale()`, so no request value can choose a file path
(the translator builds `lang/{locale}.json` from the locale string).

## Locale resolution (first match wins)
1. **User preference**: nullable `users.locale` (signed-in user chose a language).
2. **Session choice**: `session('locale')` — a guest who picked a language on the login page; carried through sign-in.
3. **Workspace default**: the existing, previously unused workspace setting `language` (reused, not a new key),
   only for the workspace the request is acting in (`Tenant::current()`, set by `SetCurrentWorkspace` after its
   membership check). Never read from another workspace.
4. **Accept-Language**: the browser's preferred languages, matched on the primary subtag (`ur-PK` → `ur`).
5. **Config fallback**: `config('app.fallback_locale')` (if supported) else `en`. Not `app.locale`: `App::setLocale()`
   writes the chosen locale back into `app.locale`, so in a long-lived worker (Octane, queue, tests) it would carry
   one request's language into the next (caught by a test during this cycle).

## Where it lives
- `App\Support\Locale` (next to `Direction`): `supported()`, `isSupported()`, `match(?string)` (normalise + allow-list),
  `fromAcceptLanguage(Request)`, `resolve(?User, ?string $session, ?Workspace, Request): string`. Pure, no side effects.
- `App\Http\Middleware\SetLocale`: in the `web` group; ordered after `SetCurrentWorkspace` via the middleware
  priority list so the tenant default is visible on workspace routes. Calls `App::setLocale()` and adds
  `Vary: Accept-Language`. `Direction` keeps deriving `<html lang dir>` from the app locale (unchanged).
- `App\Http\Controllers\App\LocaleController@update` — `POST /locale` (name `locale.update`), CSRF-protected, throttled,
  open to guests and users. Single write path: validates against the allow-list (empty = "use default"),
  stores it in the session and, when signed in, in `users.locale`. Redirects back only to a same-host URL.
- Error pages for unmatched routes (which skip the `web` group) get the browser language via a pass-through
  exception `render` hook in `bootstrap/app.php` (Accept-Language → fallback only; no session there).
- Workspace default: a "Default language" select in Settings › General, saved to the `language` setting.
- Switchers: profile page (full form incl. "Workspace default"), compact select in the sidebar and on guest/auth
  pages. Each option is the language's own name with its own `lang` attribute; the select has a label;
  a no-JS submit button is kept.
- Widget: `widget.js` stays one cached, locale-free script. It sends `data-locale` (embed attribute) or the host
  page's `<html lang>` to `/widget/{key}/config?locale=`; the endpoint resolves query → workspace default →
  fallback through `Locale::match` and returns `locale`, `dir` and the chrome strings. Direction comes from the
  resolved locale when `data-locale` is set, else from the host page (v7 behaviour).

## Boundaries (slice 1)
In: shared layouts (app, guest, errors), sidebar/nav, auth pages (login, 2FA, register, forgot/reset, new
workspace), error pages, widget chrome + widget default greeting/privacy/fallback answers, the switchers.
Out (later slices): page bodies under `resources/views/app/**`, controller flash messages, validation messages in
ur/ar, mails, number/date formatting per locale, AI answer language (the Brain already answers in the user's
language), human translation review.

## Security
Allow-list validation (`Rule::in`) on every input, `Locale::match` before `setLocale`, no request value in file
paths, translations rendered only through escaped `{{ }}`/`@json` (never `{!! !!}`), CSRF on the switcher,
same-host redirect, throttle.

## Consequences
- New UI strings must be wrapped in `__()` and added to all three JSON files; tests enforce key/placeholder parity
  and that every literal `__()` key in views exists in `en.json`; a scan fails if the in-scope views gain unwrapped text.

## Review log (cycle v9)
- Diff checked against this ADR: one locale concept (`Locale`) next to `Direction`, one write path (`LocaleController`),
  the existing workspace `language` setting reused, no vendor packages. Small additions kept on purpose: guest layout
  wrapper became `<main>` (landmark), auth inputs got `id`/`for`/`autocomplete`, "Back to sign in" link on the
  forgot-password page, Nastaliq font stack for Urdu.
- Security review: allow-list on `/locale`, Settings and the widget (`Locale::match`, length-capped); no request value
  reaches a file path; translations only via `{{ }}`, `@json` and `textContent` in the widget; `/locale` is in the
  CSRF-protected `web` group (not in the except list; tested with the check forced on); off-site Referer falls back to
  `/`; `throttle:30,1`; `users.locale` is not mass-assignable (forceFill only).
- Known gaps: requests rejected before `SetLocale` (throttle 429 on a throttled route, suspended-workspace 403 from
  `SetCurrentWorkspace`) render in the browser language/fallback rather than the user preference.
